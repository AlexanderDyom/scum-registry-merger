# SCUM Registry Merger

**Несколько модов SCUM с новыми предметами одновременно, и предметы не пропадают.**

[English version](README.md)

## Проблема

Мод SCUM, который добавляет новые предметы, рецепты или постройки, обязан нести полный `SCUM/AssetRegistry.bin`:
записи самой игры плюс свои новые. Без этих записей игра не находит новые ассеты.

Но игра читает только один реестр — из пака с самым высоким приоритетом. Если в `SCUM/Content/Paks/~mods` два таких
мода, используется реестр только одного из них. **Новые предметы другого мода молча пропадают**: их нельзя заспавнить
или скрафтить, торговцы их не продают.

## Решение

SCUM Registry Merger читает реестры всех установленных модов и объединяет их с реестром игры. Результат записывается
одним дополнительным паком `~mods/pakchunk999-ModsRegistry_999_P.pak` (и `.sig`). Номер патча `_999_P` даёт ему
приоритет выше любого мода, как бы тот ни назывался. Поэтому игра берёт его реестр, а в нём есть записи всех модов.

Почему это важно: SCUM сравнивает имена паков как текст, а не как числа. Например, `pakchunk9999999-Мод_P.pak` важнее,
чем `pakchunk999-…_P.pak`. Номер патча в имени (`_N_P.pak`) сильнее любого имени. Если какой-то мод тоже использует
номер патча, программа возьмёт номер выше и предупредит, если что-то перекрывает общий реестр.

Сами моды не меняются. Чтобы всё отменить, удалите этот один пак или нажмите «Удалить реестр» в настройках.

## Как пользоваться

1. Скачайте `ScumRegistryMerger.exe` в разделе [Releases](https://github.com/AlexanderDyom/scum-registry-merger/releases).
   Это один файл без установки, .NET не нужен.
2. Запустите. При первом запуске выберите **клиент SCUM** или **SCUM Server**: программа находит их в библиотеках Steam,
   либо укажите любую папку. AES-ключ игры необязателен (см. ниже).
3. В окне — список модов из `~mods`:
   - ✔ зелёный: новые предметы мода уже в общем реестре, или реестр этому моду не нужен;
   - ✖ красный: новых предметов мода нет в общем реестре. Нажмите **«Собрать реестр»**.
4. Перед сборкой закройте игру или остановите сервер: SCUM держит свои паки открытыми.

**Запускайте программу после каждой установки, обновления или удаления мода и после каждого обновления игры.** При
запуске она сравнивает моды с последней сборкой и, если что-то изменилось, предлагает пересобрать.

### AES-ключ (необязательно, но рекомендуется)

Паки самой игры зашифрованы, паки модов — нет.

- **Без ключа** записи игры берутся из копии внутри одного из модов. Это работает, если мод собран под текущую версию игры.
- **С ключом** реестр собирается из записей самой игры, и программа замечает обновления игры.

Ключ хранится в зашифрованном виде только для вашего пользователя Windows (DPAPI) и никуда не отправляется.

### Проверка версии игры

Реестр мода несёт и записи игры той версии, под которую мод собирали. С AES-ключом программа сравнивает их с
установленной игрой. Мод, собранный под другую версию, получает пометку «другая версия игры», а пока он не в общем
реестре — ещё и оранжевый **!**. Его устаревшие записи в общий реестр не попадают, но сам мод может работать
неправильно, пока автор его не обновит.

Без ключа версию игры не проверить, и программа об этом пишет. Чтобы проверять без ключа в программе (например, на
другом компьютере с той же версией игры), один раз сделайте **эталон** своей версии игры консольной версией:

```
ScumRegistryMerger.Cli.exe make-reference --paks "<папка SCUM или SCUM Server>" --aes-file key.txt
```

Эталон сохранится в `%APPDATA%\ScumRegistryMerger\reference\<отпечаток>.ref`, и программа с консолью будут брать его
оттуда сами, когда ключ не указан. Файл можно скопировать на другие компьютеры с той же версией игры. В эталоне только
64-битные хеши имён записей игры, без имён файлов и содержимого игры, и он никуда не отправляется. После обновления
игры его нужно сделать заново. Если все установленные моды собраны под другую версию, программа попросит AES-ключ, а не
соберёт реестр из устаревших записей.

### Выделенный сервер

При первом запуске выберите *SCUM Server*. На сервере без рабочего стола есть консольная версия, она делает то же самое:

```
ScumRegistryMerger.Cli.exe --paks "C:\SCUMServer" [--aes-file key.txt] [--dry-run]
```

## Безопасность и честная игра

- Программа только читает паки игры и пишет один пак в `~mods`. Ваши моды и файлы игры она не трогает.
- Моды — для одиночной игры и серверов, которые их разрешают. Не заходите с модами на официальные и защищённые серверы.
- SCUM и все её ресурсы принадлежат Gamepires / Jagex. Это фанатская утилита, с ними она не связана. Программа
  читает только установленные у вас файлы игры и никуда их не распространяет; AES-ключ не хранится ни в этом
  репозитории, ни в релизах. Подробнее — [THIRD-PARTY-NOTICES.md](THIRD-PARTY-NOTICES.md).

Как это устроено внутри и как собрать из исходников — в [английском README](README.md#how-it-works-for-modders).
